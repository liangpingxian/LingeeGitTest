# 点单小程序 · 架构基线

- 工作项：wi-t1000001
- 需求基线：`docs/wi-t1000001/requirements.md`（sha256:8915fc24774864692e35333d7deebfaecec7d40ae82350d770677409fd4b3a20）
- 应用类型：simple-frontend（compact 路线；纯前端本地数据，无服务端）

## 1. 应用形态与页面范围

单页应用（React + Vite SPA），在同一应用内提供两个界面视图，顶部导航切换，无后端路由：

- **顾客点单界面**
  - 菜单列表：展示内置示例菜品的名称与价格。
  - 点单操作：菜品可加入点单、增减数量；所选菜品、数量与合计金额（各菜品单价×数量之和）随调整即时更新。
  - 提交与确认：提交点单后展示订单确认，含唯一订单编号、菜品明细（名称、数量、单价）与合计金额。
- **商家订单界面**
  - 订单列表：展示当前浏览器内已提交订单的编号、合计金额与状态。
  - 订单明细：可查看单个订单的菜品明细。
  - 完成标记：可将订单标记为已完成，列表与明细中的状态可见地变化。

界面文案使用中文。

## 2. 数据归属与读写边界

全部数据由应用在当前浏览器内读写；不引入服务端、数据库、认证、后台任务或外部集成。

- **菜品菜单**：代码内置的示例常量（名称、价格），不持久化，不提供维护界面。
- **订单数据**：写入浏览器 `localStorage` 单一 JSON 条目（键 `orders`）；每条订单含唯一订单编号、菜品明细（名称、数量、单价）、合计金额与状态（未完成/已完成）。订单编号由应用在当前浏览器数据生命周期内单调递增生成，保证唯一。
- **持久边界**：数据在同一浏览器配置文件中刷新或重新打开后仍保留，满足"订单在当前使用会话中（含页面刷新）可通过商家侧界面读回"（需求 R4）；数据不与其他浏览器、设备或用户共享，清空浏览器站点数据即回到初始状态。

## 3. UI 选型与视觉方向

- 组件体系：Ant Design（`antd`、`@ant-design/icons`）。新建 React 应用且无既有设计系统或不兼容约束，适用共享 UI 默认方案；商家订单界面为轻量管理工作台形态。
- 视觉方向：浅色工作区，清晰标题与主操作（提交点单、标记完成为高亮主按钮）；顾客界面以菜品列表与点单汇总区组织内容，商家界面以订单列表（含状态标识）组织内容。
- 实现参考：团包内 `experts/general-app-development-expert/skills/general-app-implementation/assets/antd-workbench/example.jsx` 与 `example.css`；示例数据与占位文案不构成业务需求。

## 4. 实现入口与运行方式

- 新建应用在授权写入目录内初始化为 React/Vite 项目（npm）。
- 运行方式：Vite 开发服务器（`npm run dev`）；生产构建为静态 SPA。

## 5. 设计边界

- 点单提交为浏览器本地动作，不含在线支付，不生成任何服务端或同步层。
- 不扩展需求语义：菜品维护、桌号、会员、优惠券、跨设备/跨用户同步均不在本基线范围内。
