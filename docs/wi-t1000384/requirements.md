# 工单系统需求（T1000384）

## 目标

开发一个工单系统，支持工单从创建到处理完成的完整闭环。（用户明确提出）

用户输入仅包含该目标，未指定角色、流程细节、优先级或非目标。以下推荐基线仅用于闭合核心目标所必需的最小范围，均可调整。

## 核心行为与规则

### 工单创建（用户明确提出 / 推荐基线闭合）

- 用户可创建工单，填写标题、问题描述，必要字段为：标题、描述。（推荐基线：无标题或无描述时创建失败并给出错误反馈，不允许产生空工单。）
- 创建成功后，工单进入初始状态「待处理」，并可在工单列表中被查询到。（读取行为可读回，创建结果可观察。）

### 工单处理（推荐基线）

- 处理人可查看工单详情，并回复工单；回复内容追加到该工单的沟通记录中，不覆盖已有回复。
- 处理人可将工单标记为处理完成；完成前工单处于「处理中」状态。
- 状态流转限定为：待处理 → 处理中 → 已完成；不允许跳过中间状态或从已完成回退。（推荐基线，用于保证生命周期可观察、可验收。）

### 工单查看（推荐基线）

- 用户可查看工单列表，每条工单可见其标题、当前状态。
- 用户可打开单个工单查看详情，包含描述与历史回复。

### 未规定事项（不纳入本次基线，不生成验收）

- 用户角色体系、权限分配与组织归属方式。
- 通知、SLA 时效、超期提醒、统计报表。
- 数据长期持久化技术、部署方式与运行环境。
- 客户端形态（页面布局、设备适配等）。

## 验收标准

### AC-01：用户可创建工单并读回
- 验收条件：用户填写标题和描述提交后，工单创建成功，且该工单在工单列表中可见、状态为「待处理」。
- 入口类型：用户界面
- 验证动作：在工单创建入口填写标题与描述并提交，随后打开工单列表。
- 预期结果：列表中出现新建的工单，标题与提交内容一致，状态为「待处理」。
- 证据类型：interaction, session-persistence

### AC-02：无效输入被拒绝并反馈错误
- 验收条件：标题或描述缺失时不产生工单，用户收到明确的错误反馈。
- 入口类型：用户界面
- 验证动作：在工单创建入口不填写必填字段直接提交。
- 预期结果：提交失败，页面给出可理解的错误提示，工单列表中不出现新工单。
- 证据类型：interaction, error-feedback

### AC-03：处理人可回复并完成工单
- 验收条件：处理人对工单回复后回复内容被保存并可见；工单按 待处理 → 处理中 → 已完成 流转，且不可跳过或回退。
- 入口类型：用户界面
- 验证动作：打开一张「待处理」工单，提交回复，将工单流转为「处理中」，再标记为已完成；随后查看该工单详情。
- 预期结果：历史回复全部保留并可见，工单状态为「已完成」；已完成工单不提供再次流转为其他状态的入口。
- 证据类型：interaction, session-persistence

### AC-04：用户可查看工单详情与处理进展
- 验收条件：用户打开工单后能看到描述、当前状态与全部历史回复。
- 入口类型：用户界面
- 验证动作：从工单列表打开一张已被回复过的工单。
- 预期结果：详情中展示工单描述、当前状态，以及按时间保留的全部回复内容。
- 证据类型：runtime-render, session-persistence
