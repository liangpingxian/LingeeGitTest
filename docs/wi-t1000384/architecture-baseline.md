# 工单系统架构基线（T1000384）

本基线基于已批准的需求快照 `docs/wi-t1000384/requirements.md`（sha256: e3c61c6bbf5335a23051c3a2aae61f159f266428263c85fa655c016599f5d88f）产出，不改变其产品语义，仅给出必要的技术承载方式。

## 路线结论

本工单系统为**单用户简单前端应用**（simple-frontend，compact 路线）：全部行为在浏览器内完成，无服务端、API、权威数据库、认证、后台任务、外部集成或数据同步层。需求基线已明确将用户角色体系、通知/SLA、部署与长期持久化技术排除在本次范围之外；全部验收证据类型为交互与 session-persistence。

## 技术选型与实现入口

- 新建 **React + Vite SPA** 应用，单页路由承载列表与详情两个视图。
- 实现入口：Vite 开发服务器（`npm run dev`），验收即在该开发服务器页面上进行。

## 页面与交互范围

- **工单列表页**：展示全部工单的标题与当前状态，并提供创建工单入口。
- **工单创建**：表单填写标题与描述后提交，创建成功进入列表；提交失败在页面上就地给出错误反馈，不产生新工单。
- **工单详情页**：展示描述、当前状态与全部历史回复（按时间追加、不覆盖），并提供回复输入与状态流转操作入口。

## 数据归属与读写边界

- 所有工单数据由应用统一读写并持久化到浏览器 `localStorage`（单一存储键，由应用负责序列化/反序列化）。数据在同一浏览器配置文件中刷新或重开页面后仍保留，不与其他浏览器、设备或用户共享。
- 数据记录形态只承载需求基线已定义的字段：工单标识、标题、描述、当前状态（待处理/处理中/已完成）、回复记录（内容与时间）及创建时间。状态字段仅承载基线定义的三种取值，流转由界面操作触发，应用在写入时保证单向流转不被跳过或回退。
- 校验边界：创建提交在客户端校验标题与描述非空，空值时拒绝写入并回显错误提示；回复为非空文本后追加到该工单的沟通记录。

## 可重复验证说明

本应用各验收路径均为用户手动触发的确定性流程（创建、回复、状态流转、查看），无自动推进、随机结果、定时任务或外部异步事件，无需额外的应用侧测试控制入口。验收时按正常产品路径操作即可；如需恢复初态，清除浏览器中本应用的 localStorage 存储键后重新创建数据。
